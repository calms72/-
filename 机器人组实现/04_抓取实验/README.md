# 空纸盒预设抓取与六轴姿态演示

本目录可在无设备的电脑上复现两件事：检查空纸盒准备、抓取的控制逻辑，生成石头剪刀布或三组物料姿态的 CAN 指令轨迹。连接设备时，空纸盒程序通过 USB 串口进入 MP257 Linux 控制板，旧版姿态演示通过 SSH/SCP 向同一类控制板提交轨迹。两条路线均由板端 can-utils 驱动灵巧手。

## 先在电脑上验证

以下命令从本 README 所在目录执行。离线部分只使用 Python 标准库，本次在 Windows、Python 3.12.4 上复核。每条预览、测试或轨迹生成命令都不需要安装串口依赖或打开设备。

```powershell
py -3.12 .\代码\test_paperbox_grasp_simple.py
py -3.12 .\代码\paperbox_grasp_simple.py
py -3.12 .\代码\paperbox_grasp_simple.py prepare
py -3.12 .\代码\paperbox_grasp_simple.py grasp
```

测试文件使用模拟串口和模拟时钟，6 个测试方法全部通过。它们覆盖准备及抓取指令的批次与顺序、只读状态查询、预览不打开串口、输入姿态和故障检查，以及通信中断或缺失应答时不自动重发。其余三条命令都会输出 `mode=offline_preview`、两组预设和 `opens_serial=false`。

### 离线生成其他姿态

| 命令 | 默认输出（本目录下） | 本次逐帧核对 |
|---|---|---:|
| `py -3.12 .\代码\rps_demo.py` | `运行记录/rps_can.log`，一轮石头、剪刀、布及复位 | 5,940 帧 |
| `py -3.12 .\代码\material_grip.py --mode manual` | `运行记录/grip_manual_can.log`，食指单轴运动 | 5,520 帧 |
| `py -3.12 .\代码\material_grip.py --mode cylinder` | `运行记录/grip_cylinder_can.log`，圆柱位姿 | 5,520 帧 |
| `py -3.12 .\代码\material_grip.py --mode box` | `运行记录/grip_box_can.log`，方形位姿 | 5,520 帧 |

每组六帧按六个电机 ID 排列。这四个文件是脚本生成的期望控制轨迹；重复执行会重写同名输出。表中数字仅适用于默认轮数、默认保持时长。用于纸盒现场验收的是下节的专用预设；旧版 `--mode box` 指方形积木位姿。

## 空纸盒实机入口

同款平台包括 ELF 六自由度灵巧手、MP257 Linux 控制板，以及 USB 调试串口。电脑需能通过 `py -3.12` 启动 Python，实机模式还需要 `requirements.txt` 中的 pywin32。板上需有 candump、cansend 与 timeout，CAN 接口为 1 Mbit/s，程序会检查板型、当前运行的控制进程及六轴状态。默认 COM12，实际端口不同可在命令行传入 `--port COM数字`。开始前依照设备说明做好限位和断电准备。

| 步骤 | 文件及作用 |
|---|---|
| 1. 空手准备 | 确认没有其他控制程序驱动手指，拇指侧摆已达 2000±20。双击 `代码/1_准备放物.cmd`，等到准备姿态就绪。 |
| 2. 放置空纸盒 | 操作者按已标定方向放置并支撑与该预设匹配的纸盒，手和衣物退出闭合区域。 |
| 3. 执行抓取 | 双击 `代码/2_执行抓取.cmd`。程序一次提交五个弯曲轴目标，保持侧摆不动，随后读取六路反馈。 |
| 状态与停止 | `代码/查看状态.cmd` 会连接实机读取状态。 `代码/3_停止后续动作.cmd` 取消以后的提交，已发到板上的批次可能继续执行；不能将此按钮当作硬件急停。 |

实机命令行入口为 `paperbox_grasp_simple.py prepare --run` 与 `paperbox_grasp_simple.py grasp --run`，分两次执行。现场状态异常或总线反馈不全时，程序终止此次提交，不自动继续、张开或加力。另一套旧版姿态发生器如需上机须显式传入 `--run --host <本机已确认的控制板地址>`，并具备经授权的 SSH/SCP 与板端 canplayer。物料脚本的位姿和拇指侧摆上限与纸盒程序不同，迁移设备时需按设备实际限幅核对。

## 实机记录能支持的结论

11 月 11 日的空纸盒交付记录保存了两轮“空手准备 → 操作者放置并支撑纸盒 → 带盒抓取”。六轴依次为拇指侧摆、拇指弯曲、食指、中指、无名指和小指。表中均为驱动器原始位置计数。

| 阶段 | 预设 | 第一轮末次反馈 | 第二轮末次反馈 | 两轮最大绝对偏差 |
|---|---|---|---|---:|
| 空手准备 | 2000, 612, 0, 0, 0, 0 | 2000, 588, 0, 0, 3, 3 | 2000, 588, 0, 0, 0, 0 | 各 24 |
| 带盒抓取 | 2000, 1562, 1710, 1709, 1101, 1008 | 2000, 1565, 1713, 1715, 1104, 1017 | 2000, 1565, 1710, 1715, 1110, 1017 | 各 9 |

位置反馈符合当次 ±30 计数的判据。实验报告独立记录了操作者对指定空纸盒的现场成功确认。程序判定为 `preset_reached_grip_unverified`，表示仅靠位置传感器无法确认夹持。现有记录未测悬空提起、夹持力、抗滑能力或成功率。预设 JSON 保存了定稿前的阶段说明；上表来自后续正式运行记录。

早期正方体积木多次测试没有稳定夹住。装水的 550 mL 矿泉水瓶曾靠手掌短时托住，未验证稳定夹紧。这两组探索还涉及 `contact_grip.py` 的位置滞后判据、`hold_grip.py` 的板端持续保持与主动释放。其关键现象需要设备和物体才能观察，已有离线轨迹只能说明将发送哪些姿态。上述两份探索程序没有纳入本项可复现演示。

## 代码和证据来源

- `代码/paperbox_grasp_simple.py` 是正式纸盒入口，`代码/paperbox_grasp.py` 提供协议检查与串口工厂，`代码/纸盒抓取预设.json` 保存固定值，`灵巧手网页控制台_Windows运行版/web/serial_console_windows.py` 提供 Windows 串口会话，保持该相对路径。四个 cmd 是原操作入口。
- 空纸盒源码、参数、六组测试及上表来源于团队《实验24_空纸盒预设抓取实验报告_20261111》和同次交付包中的 `可复现代码/evidence/证据说明.json`。测试中的板端启动标识在此版本换为合成测试值；控制实现及动作预设保持原字节。
- `代码/rps_demo.py`、`代码/material_grip.py` 来自团队 `调试工作区/代码`。公开副本移除了历史现场默认地址，实机操作必须提供 `--host`；离线轨迹按原实现生成。积木、水瓶结果来自团队《实验24_物料抓取_实验记录》及《实验24_特定物料抓取_实验报告_核实版》。
